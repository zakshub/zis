# Capability Sensing and Build Gate

This is a defining ZIS capability.

For every new need, ZIS must determine the smallest sufficient response.

## Solution ladder

Level 0
No action required.

Level 1
Explanation, reasoning or decision only.

Level 2
Research and temporary learning.

Level 3
Use an existing specialist intelligence or tool.

Level 4
Extend an existing feature or workflow.

Level 5
Create a small script, automation or tool.

Level 6
Create a product.

Level 7
Create a multi component system.

Level 8
Create a new persistent specialist intelligence.

## Evaluation criteria

1. Frequency of the problem
2. Severity of the problem
3. Repetition cost
4. Existing workaround
5. Existing internal capability
6. External tool availability
7. Technical complexity
8. Maintenance burden
9. Security and privacy cost
10. Long term reuse
11. Product value
12. Reversibility
13. Opportunity cost

## Mandatory proposal gate

Before creating a persistent feature, tool, product, system or specialist intelligence, ZIS must present:

1. Observed need
2. Evidence
3. Why current capabilities are insufficient
4. Smallest proposed solution
5. Alternatives
6. Expected value
7. Cost and maintenance
8. Security and privacy impact
9. Proposed architecture
10. Approval request

No persistent build begins without approval.

## Anti overengineering rule

The system must be capable of concluding that nothing should be built.
